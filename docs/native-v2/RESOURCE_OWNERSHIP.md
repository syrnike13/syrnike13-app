| Monitor pattern fixture | `monitor_pattern_fixture.exe` test process plus kill-on-close Job Object | One UI/message thread | After selected-monitor resolution | Probe scope exit, constructor failure, timeout, or process termination | Placed from selected monitor bounds; parent process owns the child even on forced termination | No |

The utility is deliberately app/session scoped, which avoids repeated SDK initialization and provides a stable owner for the warm microphone. Credentials and desired room state remain connection-epoch scoped, so a long-lived utility does not retain expired authority. Async Room callbacks capture weak shared mailbox/state objects rather than raw owners. A utility epoch with a non-returning SDK operation is never reused, because process replacement is the only safe way to reclaim that unknown native ownership. A completed failed screen submission returns its borrowed slot and still drains through ordered unpublication; its media failure alone does not imply an unresponsive SDK.

The product Engine connects source enumeration and existing WGC/DXGI capture through `ScreenOwner`; Electron receives opaque source metadata and bounded thumbnail results. The Media Lab's `lab::ReferenceScreenSender` remains an independent oracle; its synchronous lifecycle and owning Room pointer are excluded from production. The source adapter closes temporary process handles before returning bounded values; only the documented diagnostic debug device and bounded exact live-target capture-item cache survive an individual capture session.
