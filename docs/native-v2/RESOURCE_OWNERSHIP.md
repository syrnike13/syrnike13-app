| CPU reference worker and LiveKit objects | `lab::ReferenceScreenSender` | One joinable worker plus synchronous caller-side publish/unpublish | Lab publication start | A returning stop releases track/source/output; process termination is the boundary for a non-returning call | Direct `Room`, participant, `VideoSource`, and `LocalVideoTrack` ownership is allowed only in the disposable oracle; it is forbidden as a production dependency | No; lab process only |
| Production screen publication | Room/media-session owner (planned #121) | Bounded asynchronous operation lane | Accepted generation command | Acknowledged unpublish or media utility epoch retirement | No Room pointer crosses the seam; fixed command/event/slot capacities and typed operation deadlines | Room scoped; encoded slots are generation scoped |
| Monitor pattern fixture | `monitor_pattern_fixture.exe` test process plus kill-on-close Job Object | One UI/message thread | After selected-monitor resolution | Probe scope exit, constructor failure, timeout, or process termination | Placed from selected monitor bounds; parent process owns the child even on forced termination | No |

The utility is deliberately app/session scoped, which avoids repeated SDK initialization and leaves a stable owner for the future warm microphone. Credentials and desired room state remain connection-epoch scoped, so a long-lived utility does not retain expired authority. Async Room callbacks capture weak shared mailbox/state objects rather than raw owners. A utility epoch with a non-returning SDK operation is never reused, because process replacement is the only safe way to reclaim that unknown native ownership.

Source enumeration and WGC monitor/window capture are not connected to the product Engine, addon, or Electron. The Media Lab alone connects them to LiveKit through `lab::ReferenceScreenSender`; its synchronous lifecycle and owning Room pointer are intentionally excluded from production. The source adapter closes temporary process handles before returning bounded values; only the documented diagnostic debug device and bounded exact live-target capture-item cache survive an individual capture session. See [MONITOR_CAPTURE.md](MONITOR_CAPTURE.md), [WINDOW_CAPTURE.md](WINDOW_CAPTURE.md), and [SCREEN_PUBLICATION_SEAM.md](SCREEN_PUBLICATION_SEAM.md) for callback, generation, event, lease, and future publication ownership.
