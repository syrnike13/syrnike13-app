# ADR-0010 — Сезонность через каталог дат и варианты иконок

- **Status:** Accepted
- **Date:** 2026-10-20

## Контекст

К праздничным датам хочется сезонных деталей в интерфейсе. Первая попытка
сделала общий слой эффектов: реестр `holidayId → slot → component`,
`<HolidayEffects slot="…" />`, CSS-хук `data-holiday` и dev-панель для
переключения праздников. Пользовательские украшения и инструменты разработчика
нужно разделять: удаление artwork не требует удаления панели предпросмотра.

Требования изменились: состав и вид сезонных деталей определяет владелец
продукта, система должна только знать, когда наступает дата, и не диктовать,
что именно рисовать.

## Решение

- **Каталог** живёт в `@syrnike13/ui/holidays`
  (`packages/ui/src/holidays`): окна задаются локальными днями `MM-DD` без
  года, `from > to` означает переход через Новый год. Время суток и таймзоны
  не учитываются — сезонность идёт по локальным часам зрителя.
- **Резолвер** — чистые функции `toMonthDay` / `resolveActiveHoliday`;
  сохраняется каталог праздников и приоритеты пересекающихся окон. Каталог
  сам по себе ничего не рисует.
- **Провайдер** `HolidayProvider` монтируется в корне приложения,
  перепроверяет дату раз в минуту и публикует активный праздник через
  `useActiveHoliday()`. Без провайдера хук возвращает `null`.
- **Иконки** — единственная сезонная поверхность. Вариант регистрируется в
  реестре через `defineHolidayIcon(base, source, { holidayId: Glyph })`; имя
  иконки (`HomeIcon`) стабильно, вне окна рендерится базовый глиф. Сейчас
  сезонная иконка одна: `HomeIcon` → тыква на Хэллоуин.
- **Dev-панель сохраняется:** `DevToolsOverlay` объединяет Holidays и Prism.
  Через `useHolidayPreview()` можно выбрать праздник вне его даты, выключить
  сезонность или вернуться к календарю. Выбор сохраняется в localStorage
  только при переданном `overrideStorageKey`; приложение передаёт его в DEV.
- **Слоя эффектов нет:** ни реестра эффектов, ни слотов, ни `data-holiday`.
  Каждый новый сезонный глиф — отдельное решение, а не следствие «системы».

## Последствия

- Новый праздник — запись в каталоге; новый сезонный глиф — вариант в
  `defineHolidayIcon` и файл с artwork в `apps/web/src/components/icons/holiday/`.
- Любые визуальные эффекты (снег, оформление, оверлеи) добавляются по явному
  запросу отдельной задачей со своим дизайном, а не через общий
  `holiday-effects`-слой.
- Проверить сезонный глиф вне его даты можно через вкладку Holidays в DEV,
  без изменения системной даты. Prism сохраняет настройки и экспорт JSON.
- Landing и admin могут переиспользовать каталог и провайдер, но собственных
  реестров эффектов пакет больше не требует. Названия праздников для dev-панели
  остаются в каталогах переводов web.
