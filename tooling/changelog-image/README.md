# Картинки для чейнджлогов

```sh
node tooling/changelog-image/generate.mjs tooling/changelog-image/releases/0.8.1.mjs
```

PNG 1600×900 появится в `tooling/changelog-image/out/` (не коммитится). Нужен Chrome или Edge; другой путь — через `CHROME`.

Новый релиз — новый файл в `releases/`: `version`, `theme` (цвета, фон, декор) и плитки. Мини-макеты UI лежат в `mockups.mjs`; новая фича без подходящего макета — новая функция там же. Текст поста кладём рядом: `releases/<версия>.md`.

## Правила

- **Показывать, а не рассказывать.** На картинке только бренд, крупная версия и 3–4 плитки: заголовок в одно-два слова и макет фичи. Абзацев нет.
- **Сезон — через фон, палитру и мелкий декор** (паутина, паук, тематические эмодзи в макетах). Маскот в праздничных декорациях не рисуем.
- **Не спойлерить экраны загрузки.** Никакого логотипа или сырника в центре с декором вокруг — это композиция экрана загрузки, даже со своими спрайтами. Спрайты из `cake-logo-*.tsx` не берём.
- В пост попадает только то, что вышло в production: nightly-only фичи и скрытые сюрпризы не упоминаем. Пункты собираем из `git log v<prev>..v<new>`.
- Шрифты проекта: Space Grotesk для цифр и латиницы (кириллицы в нём нет), Nunito Sans для русского текста.

## Текст поста

Заголовок с эмодзи и версией, затем разделы с теми же названиями, что у плиток, по одному-два коротких предложения на «ты». В конце «Исправили» списком. Детали, в которых не уверены (например, точные shortcode эмодзи), проверяем в приложении до публикации.
